# R13 production identity inventory

**Scope:** repository evidence for the existing machine/service identity fabric, read on 2026-09-27. This is an inventory for the Knowledge R13 production-mechanism decision, not a deployment design or live host inspection. `PROVEN` below means implemented in source or reported by the dated production closeout; `DOCUMENTED` means a deployment rule without independent inspection here; `INFERENCE` identifies a conclusion drawn from those sources.

## 2. Session and local service path

- **BFF and delegated session — PROVEN.** The Nuremberg BFF is a confidential OAuth client; its server keeps client secret, OAuth tokens and PKCE verifiers, while the browser gets an opaque Secure/HttpOnly/SameSite cookie. Its SQLite session store is owned by `svc-home-bff`, directory `700`/file `600`, excluded from backup; sessions expire in 12 hours. [`docs/architecture/DEPLOYMENT.md:45-72`](../DEPLOYMENT.md#L45), [`services/home-bff/home_bff/sessions.py:21-45`](../../../services/home-bff/home_bff/sessions.py#L21). Home's `open_session` uses the freshly authenticated human OAuth token and stores the Frappe User without a caller-supplied user field; `close_session` checks owner and marks it revoked. [`apps/episteck_home/episteck_home/identity/session.py:63-116`](../../../apps/episteck_home/episteck_home/identity/session.py#L63).
- **Delegation — PROVEN.** The BFF signs an HMAC-SHA256 token with opaque `sid`, issuer, single `aud`, `iat`, `exp`, and random `jti`, with 120-second mint TTL. Home verifies signature/issuer/audience/time and caps lifetime at 300 seconds, then atomically claims the `jti` in shared Redis; replay-store failure denies. Session revocation or disabled User denies even an unexpired token. [`services/home-bff/home_bff/sessions.py:92-129`](../../../services/home-bff/home_bff/sessions.py#L92), [`apps/episteck_home/episteck_home/identity/delegation.py:45-53`](../../../apps/episteck_home/episteck_home/identity/delegation.py#L45), [`apps/episteck_home/episteck_home/identity/delegation.py:94-181`](../../../apps/episteck_home/episteck_home/identity/delegation.py#L94), [`apps/episteck_home/episteck_home/identity/auth_hook.py:150-185`](../../../apps/episteck_home/episteck_home/identity/auth_hook.py#L150), [`apps/episteck_home/episteck_home/identity/auth_hook.py:188-219`](../../../apps/episteck_home/episteck_home/identity/auth_hook.py#L188). **INFERENCE:** single use limits replay after first acceptance, but this human delegation is verified together with the Home machine credential and is not R13's downstream holder-of-key execution proof.
- **Mint gateway — PROVEN in code and production closeout.** `home-agent` (uid `1003`) reaches only the standalone nginx gateway on loopback `:9934`; `svc-home-gateway` (live uid `999`) can reach direct MCP ports `:9931/:9932`. The nftables OUTPUT policy enforces those local UID/port paths. Every gateway request mints over a `0660` Unix socket accessible to `svc-home-gateway`, copies only the fresh delegation to Home/Nutrition MCP, overwrites an inbound delegation, strips Authorization/Cookie, and hides the response delegation. [`deploy/gateway/episteck-gateway.nft:4-18`](../../../deploy/gateway/episteck-gateway.nft#L4), [`deploy/gateway/nginx-mcp-gateway.conf:23-85`](../../../deploy/gateway/nginx-mcp-gateway.conf#L23), [`docs/architecture/G1_6_VALIDATION.md:37-95`](../G1_6_VALIDATION.md#L37). The BFF mint is a separate rootless socket-only process; it resolves a fixed runtime binding instead of accepting an arbitrary session identifier. [`services/home-bff/home_bff/internal_app.py:19-51`](../../../services/home-bff/home_bff/internal_app.py#L19), [`deploy/home-bff/home-bff-mint.container:7-19`](../../../deploy/home-bff/home-bff-mint.container#L7).

Nutrition `svc-nutrition` is uid `1005`, Home MCP `svc-home-mcp` uid `1006`, BFF `svc-home-bff` uid `1007`; rootless Podman/Quadlet is the Nuremberg pattern. | Tailscale and TLS | The Ashburn/Nuremberg mesh has documented node addresses; Home MCP/Nutrition resolve the Home hostname to Ashburn's Tailscale address and retain TLS hostname verification. | Public nginx/BFF | Only BFF public 80/443 is exposed on Nuremberg; app `:9933` is loopback. The public nginx allowlist denies `/delegation`, logs path rather than query (to avoid OAuth code/state leakage), and proxies only listed login/session routes; `/bootstrap` stays local. ## 4. R13 gap and evidence grade

The existing production path authenticates a machine to **Home**, then binds a separately authenticated human session, and Nutrition asks Home to authorize every sensitive operation. The gateway and filesystem controls isolate who can obtain a delegation locally. **INFERENCE:** none of these controls alone gives a domain a request-bound, non-bearer proof that the presenter of a Home-produced execution basis is the service identity and confirmation key bound to that basis. This is exactly the R13 production work left open by the technology-gate report. [`docs/architecture/SECURITY_AND_CONSENT.md:51-72`](../SECURITY_AND_CONSENT.md#L51), [`docs/architecture/proposals/KNOWLEDGE_TECHNOLOGY_GATE_SPIKE_REPORT.md:926-929`](KNOWLEDGE_TECHNOLOGY_GATE_SPIKE_REPORT.md#L926).

The Phase-1 R13 rule requires a trusted binding of **both** authenticated service identity and accepted confirmation key; a key introduced only in request payload cannot establish machine identity. It expressly selects **no production** key registration, certificate issuance, enrolment, rotation or revocation mechanism. [`docs/architecture/proposals/KNOWLEDGE_TECHNOLOGY_GATE_PHASE1.md:734-756`](KNOWLEDGE_TECHNOLOGY_GATE_PHASE1.md#L734). The synthetic spike combined ephemeral local mTLS identity with an Ed25519 proof and passed the wrong-identity/genuine-key attack on its wire path; its own report says this is single-host loopback evidence with no production CA, external network or long-lived key material, and selects no production technology. [`docs/architecture/proposals/KNOWLEDGE_TECHNOLOGY_GATE_SPIKE_REPORT.md:315-364`](KNOWLEDGE_TECHNOLOGY_GATE_SPIKE_REPORT.md#L315). The gate report still lists production identity fabric, key distribution and §11.4.1 binding as pre-runtime work. [`docs/architecture/proposals/KNOWLEDGE_TECHNOLOGY_GATE_SPIKE_REPORT.md:926-929`](KNOWLEDGE_TECHNOLOGY_GATE_SPIKE_REPORT.md#L926).

**Decision-relevant unknowns from these repository sources:** which production principal authenticates each R13 caller to the domain; how Home and the domain learn the same service↔confirmation-key binding without a caller claim; key issuance/storage/overlap/rotation/revocation and recovery; whether transport termination preserves the authenticated identity to the verifier; and how the binding is audited. These are **not claims that the live host lacks undocumented controls**: this inventory did not inspect production configuration or secret values. The existing BFF OAuth client, Frappe API Users, Tailscale route, UID/nft boundaries and short-lived delegations are concrete inputs to that decision, not evidence that the R13 production mechanism has been selected.
